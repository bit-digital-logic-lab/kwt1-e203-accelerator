# 本科 FFN1 的任务级数据流审视（2026-10-16）

## 原题给出的边界

- 本科必做为长度 64 点积、`99×64 × 64×256 + bias → 99×256` 第一前馈线性层，以及 E203 集成与综合；GELU 和第二线性层选做。见原题[第 5 页](<../../题目/640.jpg 6>)和[第 7 页](<../../题目/640.jpg 8>)。
- 系统有 512 KB 共享 SRAM、150 MHz 统一时钟；AI Engine 从 System Bus **或** NICE 接入。加速器内部存储只能用指定的 `16 bit × 128/1024/4096` 单口或双口 SRAM 宏组合。见[第 3 页](<../../题目/640.jpg 4>)。
- 本科每次任务必须从输入及参数开始装载，到全部结果写回为止；参数装载、总线等待和 E203 调度都计时。每次开始前任务数据与参数缓存清空。十二层参数各自要跑一次，精度须逐层过关。见[第 11 页](<../../题目/640.jpg 12>)。
- 必须提交与 RTL 逐位一致的数值模型，内部 SRAM 宏计入 2.25 mm² 加速器面积；吞吐、能耗、面积评分使用同一合格配置。见[第 10–12 页](<../../题目/640.jpg 11>)、[面积与评分](<../../题目/640.jpg 13>)。

以上约束意味着完整任务控制、共享 SRAM 访问次数、宏数量与端口、结果布局都属于架构，不只是 PE 的 K 循环延迟。当前自建仿真总线为 128 bit，原题没有给出竞赛平台总线宽度或仲裁时序；不能把仿真带宽当作赛题平台规格。

## 现有 8×16 路径的代价

当前 [`kwt_tile_system_model.sv`](../rtl/control/kwt_tile_system_model.sv) 对每个 tile 顺序执行 `LOAD_A → LOAD_B → LOAD_BIAS → RUN_TILE → STORE_OUT`。引擎虽有 A/B 双页，[系统接线](../rtl/control/kwt_tile_system_model.sv)将 `compute_page`、`load_page` 固定为 0，DMA 和计算没有重叠。CPU 每块发一条 NICE 命令。全层测试把 A、W、偏置和描述符预先排成 tile 格式，并在第一个 NICE 请求后才开始计任务周期；这是功能测试输入，不是从常规矩阵布局出发、包含源端参数加载的完整赛题计时。

| INT16 A/W、INT32 bias/output | 每 tile | 208 tile 合计 | 一次任务必要数据 |
| --- | ---: | ---: | ---: |
| A 输入 | 1,024 B | 212,992 B | 12,672 B |
| W 权重 | 2,048 B | 425,984 B | 32,768 B |
| bias | 64 B | 13,312 B | 1,024 B |
| 输出 | 512 B | 106,496 B | 101,376 B |
| **合计** | **3,648 B** | **758,784 B** | **147,840 B** |

必要数据量假定每个 A/W/bias 从共享 SRAM 读一次、每个有效输出写一次；尚未计入描述符、总线协议开销和源端参数加载。现有值含最后 5 个补零行，合计约为必要数据量的 **5.13 倍**。A 每个行 tile 被 16 个列 tile 重读；W 每个列 tile 被 13 个行 tile 重读。偏置也重复 13 次。

计算端，[当前引擎](../rtl/pulse_array/kwt_pingpong_cacc_engine.sv)单口读 A/B，每 18 拍启动一个 K。8×16 的 128 个乘法器各 18 拍才收到一个新操作数对，K 注入阶段的平均产出为 `128/18≈7.1` 个乘积/拍。阵列面积增大时，单口供数仍限制这个速率。最近单块仿真为 4,280 拍，包含顺序 DMA、计算和结果写回；这不是平台实测性能。

## 两条架构线

### A. 保留现有乘积阵列，先修任务调度

1. 把命令改为**一次 FFN1 层任务描述符**，包含 A、W、bias、输出基址及数据格式；E203 不再逐 tile 提交 208 条阻塞 NICE 指令。引擎内部循环 16 个列组、13 个行组。
2. 一次装入完整 `99×64` A（INT16 为 12,672 B）；按列组装 `64×16` W（2,048 B），对 13 个行组复用。每个输出通道 bias 只装一次。
3. A 保持驻留；两页 W 分别供计算和下一列组预装。当前 A/B 双页不是这种用途。结果至少需要独立暂存区，才能同时写回上一 tile 与计算下一 tile。
4. DMA 支持共享 SRAM 的常规行主序输入与二维步长访问；输出按 `(row×256+col)` 写回，避免测试台事先排 tile 或把布局转换挪到不计时的软件。

这条线先降低共享 SRAM 搬运和 E203 命令开销，保留现有算术路径作为功能基线。128 个乘法器在单口供数下仍约 1/18 活跃，面积与动态功耗需要重点衡量。

### B. 将供数速率与计算并行度配平

以 **8 条行 MAC、一个 B 字/拍**作为对照架构：固定 8 个 A 行值，按 `c=0…15` 顺序读 `W[k,n0+c]`，一个 B 标量广播给 8 个乘法器。第 `c` 拍生成 8 个不同输出的乘积，分别更新 `psum[row_lane][c]`；16 拍后进入下一个 K。A 的下一组 8 个行值在当前 16 拍 B 流中预取。每个 `8×16` 输出 tile 有 `8×16×32 bit = 512 B` 部分和状态，按行设 8 个独立的读改写通道。

这个调度每拍需要 A 预取最多 1 个 16-bit 字、B 读 1 个 16-bit 字，以及 8 个部分和更新；A 和 B 来自不同存储体。两种输入共享同一个 16-bit 单口 SRAM 无法同时提供。`13×16×64×16 = 212,992` 拍是含补零行的乘积阶段下界，尚未加初次预取、清空、偏置、结果转移、总线与控制开销。它与当前 128 PE 阵列的 `208×64×18 = 239,616` 拍 K 注入时间接近，但乘法器从 128 个降为 8 个。能否胜出仍要用相同数值位宽、宏映射和任务计时实测。

该数据流每拍只有 **8 个输出拥有者**，故行分 8 bank 的 CACC 正好每 bank 接受 1 项。不能把这 8 个加法通道直接套在每拍生成 128 个独立输出乘积的方案上。部分和可存在小型双口宏或寄存器阵列；物理 shift 环若每拍移动全部状态，可能增加切换功耗，应与按址更新方案同库比较。当前 `kwt_cacc.sv` 是按址 bank，而非真正的 shift 环。

## 建议先落地的存储与重叠关系

- A 常驻：`99×64×16 bit = 12,672 B`，容量上可用两个 `16 bit×4096` 宏组成 16 KiB，保留地址余量。是否可由现有共享 SRAM 直接供数取决于平台接口；设计比较时单列共享 SRAM 流量与内部宏面积。
- W 双页：每页 `64×16×16 bit = 2,048 B`，各对应一个 `16 bit×1024` 宏。当前列组复用 13 个行组期间装下一列组；读活动页与写空闲页物理分离。
- CACC：每页逻辑 512 B。若要在写出上一 tile 部分和时计算下一 tile，需双页 CACC 或等价的宽输出暂存；仅把最终 16-bit 输出 SRAM 做乒乓，不能解除单页 CACC 的清空/导出冲突。先量化单页导出停顿，再决定是否值得增加一页。
- 输出：有效 `99×256×32 bit = 101,376 B`，从 CACC 导出并写回共享 SRAM。输出地址应明确为行主序，DMA 至少需要行跨度和列块基址；尾部 5 个填充行不写回。
- NICE 与 System Bus 只能按题目选择一种集成方式。内部任务控制、DMA 和缓存可先独立定义；外部 wrapper 待组委会平台接口到手后确定。当前“真实 NICE 命令 + 自建 128-bit 总线 DMA”的模型尚不能证明正式集成合规。

## 下一轮实施与比较口径

先在同一套数值格式下比较 A/B 两线：共享 SRAM 读写字节数、内部 SRAM 宏数量与端口、乘法器/加法器数、每 tile 有效计算拍、输出导出停顿、E203 命令次数，以及从任务参数装载到最后一个有效输出写回的总拍数。之后才扩大并行度；例如 16 行 MAC 或每拍两个 B 字需要相应增加 B 读端口、CACC 更新端口和宏/布线，不能只翻倍乘法器。

当前软件曾得到 A11W10 静态对称的 FFN1 数值候选；[软件结果](../../software/results/0.3百分比位宽与硬件取舍.md)并非 RTL 逐位验证。上述字节表统一按现有 INT16 A/W 计算，以便同条件对照；选用紧凑 W10 后要重新计算参数搬运、解包、宏布局和整个任务的时序/能耗。
