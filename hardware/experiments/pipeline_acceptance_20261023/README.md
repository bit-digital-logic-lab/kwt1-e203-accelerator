# 主验收：流水线气泡与模拟带宽（2026-10-23）

结论：旧R4单MAC/双CACC快路径正常负载的计算段气泡较小，但尾块空lane损耗明显；16位模拟共享总线未跑满。R5新控制器仍调试中，不能把旧数值直接用于新架构验收。

## 独立执行

`python3 hardware/experiments/pipeline_acceptance_20261023/run.py`

从Git提交8490830提取未经修改的DUT，与仅增加posedge观测器的TB重新构建Verilator。握手为stream_valid && in_ready，按row_mask人口统计真正有效MAC。八个99×64×256仿真均从输入独立计算Python任意精度golden（按既有32位回绕契约），每次25,344输出逐项一致，构建/运行退出0。原始运行输出见raw_runs.txt，命令/输入及源码哈希见results.json。观测器不改变DUT或原调度。

## 正常情况分解

- 总周期121,915 = 首次装载4,128 + 计算窗口117,432 + 尾部355。
- 7行块×16输出通道块×64归约×16列 = 114,688次有效喂数。计算窗口非喂数2,744周期，占2.34%；全任务非喂数7,227周期，占5.93%。
- 连续首尾握手之间内部空闲2,720周期，最大连续空闲80周期；窗口还包括最初准备阶段，因此与2,744不同。逐拍feed_ready反压计数为0，不意味着没有调度气泡。
- 实际有效MAC=99×64×256=1,622,016。16lane×114,688=1,835,008个物理槽，11.61%喂数时的lane被屏蔽（99行补至112行）；在全任务算力预算中占10.92%。总有效MAC利用率83.15%。
- 总线有效拍=输出50,688 + bias512 + A6,336 + W16,384 = **73,920**；空闲47,995，占39.37%。R4报告文字的83,920是算术错误，原始指标实际为73,920。
- 总线最少73,920拍小于理想16lane有效计算下界101,376拍，也小于当前补齐块计算114,688拍。正常案例应先优化尾块映射/调度和输出排空，再评估扩大总线，不能仅因总线空闲就判定供数不足。
- 输出每3周期接收一次时，CACC页等待61,806周期，stage_stall143,305周期；这些计数窗口重叠，不能相加当总周期。输出反压已成为主要瓶颈。
- 更早启动（预载1块）与预载3块最终周期相同，前者多出供数等待；全等齐再算（7块）反而慢3,208拍。该案例已有有效装载/计算重叠。
