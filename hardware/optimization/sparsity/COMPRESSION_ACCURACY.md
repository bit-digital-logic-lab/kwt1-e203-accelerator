# FFN1 稀疏权重压缩的精度与字节数

2026-10-19 实测。运行 `python3 hardware/optimization/sparsity/compression_accuracy.py`，输出为 [`compression_accuracy.json`](compression_accuracy.json)。输入 SHA-256、每层误差和字节数均在 JSON 内。使用冻结 A12W10 参数、480 条本地 validation 样本、12 层 `99×64 @ 64×256 + bias`；没有改训练权重或 RTL。

编码器按每层 1024 个 `(K,16 列)` 块写 16-bit 非零位图、1025 个 16-bit 字节偏移、逐块字节对齐的有符号 W10 非零值。每个阈值、每一层均执行真实 encode→decode 并断言与该阈值处理后的 INT10 权重逐位相同。阈值 0 只省原本精确为零的值，因而相对冻结 A12W10 **完全无额外数值误差**。阈值大于 0 时把 `abs(qweight) <= 阈值` 的权重置零，是有损改值实验，不是无损压缩，也未作为最终提交配置。

| 整数阈值 | 权重零率 | 编码后 12 层字节 | 相对紧密 W10 | 12 层最大 NRMSE（对 FP32） |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0.233% | 294,477 | +19.823% | 0.14705% |
| 1 | 0.690% | 293,580 | +19.458% | 0.15121% |
| 2 | 1.138% | 292,698 | +19.099% | 0.16092% |
| 4 | 2.004% | 290,990 | +18.404% | 0.25372% |
| 8 | 3.772% | 287,477 | +16.975% | 0.48510% |
| 16 | 7.280% | 280,226 | +14.024% | 1.26365% |
| 32 | 14.299% | 264,350 | +7.564% | 3.26370% |
| 64 | 27.931% | 230,925 | −6.036% | 9.11080% |

紧密 W10 是 245,760 B，现用 INT16 容器是 393,216 B，均只计 12 层权重，不计尺度、偏置、DMA 对齐和 SRAM 宏量化。阈值 0 的稀疏编码比 INT16 容器少 25.111%，但直接 W10 位打包更小。测试的阈值中，满足题目 3% NRMSE 门槛者均比紧密 W10 **更大**；首次小于紧密 W10 的阈值 64 已达 9.11% NRMSE。故当前格式下，稀疏压缩不构成有用的权重存储方案。W10 位打包保持 A12W10 数值不变，值得优先用于存储节省，但其解包逻辑、总线周期与 SRAM 面积尚未测。

误差按每层汇总全部验证样本输出的 `sqrt(sum((approx-fp32)^2)/sum(fp32^2))` 计算，报告 12 层最大值。计算使用 FP64 BLAS 承载整数点积；单点与独立 INT64 点积逐位核对，全部累加绝对值小于 INT32 上限。输出误差包含原 A12W10 量化误差。验证划分只用于本次探索评估，不能据此选最终阈值；若坚持有损置零，应在训练划分定阈值、重新核对逐层误差与 RTL 逐位一致，并在官方任务约束下验证。这里没有稀疏解码 RTL、系统周期、综合面积或功耗结论。
