# Claude 进度报告核对（2026-10-17）

该报告可作为待办清单参考，完成度百分比和工期只是估计，不能作为验收证据。
本表以本地赛题截图和可运行工程为准。

| Claude 判断 | 核对结果 | 证据与边界 |
| --- | --- | --- |
| GELU 是本科组硬依赖，应立即接入 | **错误** | `题目/640.jpg 8` 第 7 页明确写明 GELU 和第二线性层为本科选做；必做输出是第一线性层的 `99×256`。本轮不加 GELU。 |
| RTL 从未使用真实权重，12 层精度为 0% | **错误，但验证尚未闭环** | `hardware/architecture/quantized_validation0_12layers_row16_staged.json` 是一条真实验证样本、12 层、304,128 个输出的计算核逐位检查，最差层 NRMSE 为 0.17041%。它不是 600 条官方评测、也没有把真实数据送过 E203/DMA。240 条样本的 0.18216% 是软件整数模型结果。 |
| 整层 208 块未跑完 | **过时** | `hardware/optimization/integration_result.md` 记录了开源 E203 连续 208 tile 的合成数据回归，25,344 个有效输出，838,028 拍。总线和 SRAM 是抽象模型，不能推出真实平台性能。 |
| DMA/计算还没有完全重叠，二维步长搬运缺失 | **基本正确** | 当前 DMA RTL 只支持连续 16 位字；`matrix_stride_experiment.py` 只在软件小模型中核对了 B 列块和 C 行距，没有成为硬件描述符。 |
| 缺少真实工艺库的 150 MHz、2.25 mm² 证明 | **正确** | 目前 Yosys/Nangate45 仅作结构和同库相对比较，不包含正式 SRAM 宏、STA 和完整 SoC。 |
| PE 支持 INT8/16/32 和 FP3 | **表述不准确** | 现行集成的数据通路以 16 位操作数、32 位累加为主要受测配置。不能把不同精度实验等同于完整顶层的已验证支持。 |

## 当前优先顺序

1. 按赛题冻结第一线性层的数值协议与可复现向量；精度证据逐步扩到多样本。
2. 先解决二维 stride 搬运、B 列块驻留和 bank 端口/地址冲突，再比较扩大阵列。
3. 保持 K=64 部分和片内驻留，以小模块 Verilator 回归和示例库综合记录每次改动。
4. 等正式平台接口、SRAM 宏与库到手后再做 150 MHz、面积和官方精度验收。

本轮遵照用户限制，不运行整芯片或 E203 整层仿真。
