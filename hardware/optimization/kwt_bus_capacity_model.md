# 本科 FFN1 搬运 / 容量 / 周期模型修正（含 RTL 结构证据）

范围严格限定本科必做第 2 项的第一处前馈线性层：每层 `Y[99,256] = X[99,64] @ W[64,256] + b[256]`。
GELU、第二线性层、注意力、12 层编码器和分类头不在本报告内（见 [`题目/README.md`](../../题目/README.md)）。
配套脚本 [`kwt_bus_capacity_model.py`](kwt_bus_capacity_model.py) 只读本仓库 RTL 与既有报告，
不修改任何 RTL、驱动或既有架构报告。

证据分层（任何数字只属于一层，禁止跨层拼接）：

| 层 | 含义 |
| --- | --- |
| **L0 算术/解析** | 字节数、I/O 下界，无调度、无平台时序 |
| **L1 RTL 结构** | 从 RTL 源码读出的字数与端口限制、测试台计时模型 |
| **L2 E203 NICE-like 仿真** | 208 tile 整层模型，抽象 128-bit 总线 + 仿真 SRAM |
| **L3 同库综合** | Nangate45 相对标准单元面积，无宏、无 STA |

**本报告不产生赛题平台吞吐。** RTL 字数是仿真 128-bit 总线上发出的 payload；
组委会 System Bus 宽度、延迟、仲裁均未给出。

## 1. 结论摘要

1. **唯一数据量口径修正。** 既有报告写 `147,840 B`（= 未补零 A `12,672` + W `32,768` + bias `1,024` + 有效 Y `101,376`），
   把**未补零 A** 和**补零 tile 的实际物理读/写**混在一起。物理一致的两种口径是
   **有效口径 `148,480 B`**（补零 A `13,312` + W + bias + 有效 Y）与
   **填充口径 `153,600 B`**（补零 A + W + bias + 补零 Y `106,496`）。
2. **逐 tile 重装搬运。** 当前 RTL 每 tile 真的发出 A `1,024` + W `2,048` + bias `64` + out `512` = `3,648 B`，
   208 tile 合计 `758,784 B`（`47,424` 个 128-bit beat）。这**是** RTL 在仿真总线上发出的 payload（L1），
   **不是**赛题总线实测活动，字节数也不能直接当周期数。
3. **512 KiB 共享 SRAM 容量。** 12 层 16-bit 容器 W = `384 KiB`，加当前层 padded A + bias + 有效 Y + 描述符表
   = `515,584 B ≤ 524,288 B`，**能放下，余 `8,704 B`**。若再常驻 12 层 bias 则超出 `2,560 B`。
   “放不下”不成立；“余量很小、且容量 ≠ 端口带宽”才成立。
4. **吞吐瓶颈在 16-bit 宏端口与读写冲突。** 乒乓操作数存储器每拍只取 1 个 A 字 + 1 个 B 字，
   且集成把 `compute_page/load_page` 都固定为 0，装载与计算不能重叠；8×16 引擎只有 `128/18 ≈ 7.11` 乘积/拍。
   官方宏的访问延迟、端口语义、字节使能、面积/功耗均缺失，无法签核。

## 2. 修正后的唯一数据量口径（8×16）

| 口径 | padded A | W | bias | Y | 合计 | 说明 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 既有报告（混用） | 12,672 | 32,768 | 1,024 | 101,376 | **147,840** | A 用未补零，Y 用有效 |
| **唯一·有效口径** | 13,312 | 32,768 | 1,024 | 101,376 | **148,480** | A 按整 tile 物理读，Y 只写有效行 |
| **唯一·填充口径** | 13,312 | 32,768 | 1,024 | 106,496 | **153,600** | A、Y 都按满 tile 计 |

- A 补零量 `13,312 − 12,672 = 640 B = 5 行 × 64 × 2`（104 补零行 − 99 有效行 = 5，末 tile 3 行有效、5 行补零）。
- Y 补零量 `106,496 − 101,376 = 5,120 B = 5 行 × 256 × 4`。
- `147,840 = 148,480 − 640`：既有报告相对有效口径**少算**了 A 的 640 B 补零读。
- **RTL 依据**：`hardware/rtl/control/kwt_tile_system_model.sv:70-72` 对 A 固定下 `k_len*8 = 512` 字（`1,024 B`）请求，
  与 `row_mask` 无关；末行 tile 同样整块搬运。`hardware/rtl/control/tb/tb_kwt_real_layer_e203.sv:117-118`
  也把 A 按 `ROW_TILES*K*8` 字铺满，含补零行。

## 3. 逐 tile 搬运：从 RTL 字数复核 758,784 B（L1）

`hardware/rtl/control/kwt_tile_system_model.sv:70-72` 的 DMA 字数（每 tile）：

| 缓冲 | RTL 表达式 | 16-bit 字 | 字节 | 每 tile 128-bit beat |
| --- | --- | ---: | ---: | ---: |
| A | `{6'b0, k_len_q, 3'b0}` = 64×8 | 512 | 1,024 | 64 |
| W | `{5'b0, k_len_q, 4'b0}` = 64×16 | 1,024 | 2,048 | 128 |
| bias | 常数 `16'd32` | 32 | 64 | 4 |
| out | 常数 `16'd256` | 256 | 512 | 32 |
| **合计** | | **1,824** | **3,648** | **228** |

- `208 × 3,648 = 758,784 B`；`208 × 228 = 47,424` beat；`47,424 × 16 = 758,784 B`。
- 四个字数都是 8 的整数倍，`kwt_dma` 的 `LOAD_FILL`/`STORE_*`（`hardware/rtl/dma/kwt_dma.sv:146-172`）没有
  因为“尾拍仍占一个整 beat”（`:118-125` 注释）而浪费。
- 16 行候选（`16×16`）：A `2,048` + W `2,048` + bias `64` + out `1,024` = `5,184 B`/tile，112 tile = `580,608 B`。

**边界说明（必须写在数字旁）**：

- 这些字节是 RTL 在**仿真 128-bit 总线**（`kwt_ext_memory_model.sv`，`ready` 恒 1）上发出的 payload，
  属于 L1/L2 模型；**不能**当作赛题 System Bus 的真实总线活动或总线周期。
- 另有**每 tile 2 个 128-bit beat 的描述符取指**（`kwt_nice_system_model.sv:106-120`），
  208 tile 即 `6,656 B`，**不在** 758,784 B 内。
- RTL 当前**写回补零 Y 行**（`out` 固定 256 字），所以仿真搬运是填充口径；
  第 2 节的有效口径要求尾部行屏蔽写回，那是尚未实现的设计选择，不是现状。
- 字节数 ≠ 周期数：`kwt_dma` 每 beat 需要一个总线应答周期，仲裁/延迟未建模。

## 4. 共享 512 KiB 能否容纳：12 层 W + 当前 A/bias/Y + 描述符

对齐/地址规则（来自 RTL）：外部字节地址必须 **16 B 对齐**（`kwt_dma.sv:120`、`kwt_ext_memory_model.sv:30-31`）；
内部 SRAM 字 16 bit；描述符每 tile `32 B`（两个 128-bit beat）。

| 情景 | 组成 | 合计 | 是否 ≤ 512 KiB | 余量 |
| --- | --- | ---: | :---: | ---: |
| 12×W16 + padded A + bias + 有效 Y + desc | 393,216+13,312+1,024+101,376+6,656 | **515,584** | ✔ | +8,704 |
| 12×W16 + padded A + bias + **补零 Y** + desc | 393,216+13,312+1,024+106,496+6,656 | **520,704** | ✔ | +3,584 |
| 12×W16 + **12×bias** + padded A + 有效 Y + desc | 393,216+12,288+13,312+101,376+6,656 | **526,848** | ✘ | −2,560 |
| 12×W10 紧密打包 + padded A + bias + 有效 Y + desc | 245,760+13,312+1,024+101,376+6,656 | **368,128** | ✔ | +156,160 |

结论（不做“绝对放不下”的断言）：

- **能放下。** 12 层 16-bit 容器 W `384 KiB` 与当前任务的 A/bias/Y/描述符共存时仍有约 **8.5 KiB** 余量。
- 但余量很小：**只要再把 12 层 bias 也常驻，就超出 `2,560 B`**，必须按层换 bias 或压缩。
- W10 紧密打包理论上余量 > 150 KiB，但**打包/解包路径尚未实现**，不能算已得收益
  （既有报告已指明 NPZ 仍是 int16 容器）。
- **评分任务清缓存规定**（题目第 12 页）要求每任务开始前清空该任务的数据/参数缓存。
  把 12 层 W 静态放在共享 SRAM **不违反**该规定（清的是任务/加速器缓存），
  但**参数装载仍须每任务计时**，“静态驻留”不能省掉题目计时口径里的装载。
- 容量够 **不等于** 带宽够：见第 5 节；共享 SRAM 每周期端口/仲裁、内部宏端口都未闭合。

## 5. 16-bit SRAM 宏端口 / 读写冲突：当前吞吐瓶颈（L1）

结构证据（`hardware/rtl/pulse_array/kwt_pingpong_cacc_engine.sv`、`hardware/rtl/sram/kwt_operand_pingpong.sv`、
`hardware/rtl/control/kwt_tile_system_model.sv`）：

1. **每个操作数存储器只有一条读口用于计算、一条写口用于装载**，且读写页来自同一存储体
   （`kwt_operand_pingpong.sv:27-36`）。
2. 计算侧每拍 `compute_en` 只取 **1 个 A 字 + 1 个 B 字**；`READ_ISSUE` 按 `lane_index` 走到 `MAX_LANES-1`
   （`kwt_pingpong_cacc_engine.sv:178-193`）。因此**一个 K 至少 `max(rows,cols)+2` 拍**：
   - 8×16：`max(8,16)+2 = 18` 拍/K，每 K 需 8 A + 16 B = 24 字，端口峰值 2 字/拍 → 受 B 端口限。
   - 有效产出 `rows*cols/18`：8×16 = `7.11` 乘积/拍，16×16 = `14.22` 乘积/拍（理论 128 / 256）。
3. **读写冲突被“固定同页”放大成串行**：`kwt_tile_system_model.sv:90` 把 `compute_page`、`load_page` 都接 `0`，
   于是 `load_ready = !busy`，DMA 装载与计算**完全不能重叠**；乒乓机制形同虚设。
4. **32-bit 状态放在 16-bit 宏上的读改写**：CACC 部分和与输出暂存是逻辑 32-bit
   （`out_mem` 每结果占两个 16-bit 字，`kwt_pingpong_cacc_engine.sv:131-141`）；
   16 行 row-broadcast 核每拍要更新 16 个 INT32 位置（`kwt_row_broadcast_tile.sv:58-112`），
   单 16-bit 宏需拼宽/多 bank/停顿，容量够不代表每拍带宽成立。
5. **共享数据路径下界**：`758,784 B = 379,392` 字，单 16-bit 字/拍即 `379,392` 拍；
   有效口径 `148,480 B = 74,240` 字；理想 128-bit 为 `47,424` 拍。这些是 I/O 下界，不是实测。

**官方宏参数缺失（必须标注为缺失，不能替组委会假定）**：

- 16-bit SRAM 宏的**访问延迟 / 最小周期**；
- **单口 vs 真双口**语义、字节使能；
- 宏的**面积与功耗**（2.25 mm² 与能耗估计无法闭合）；
- 赛题 **System Bus 宽度、延迟、仲裁**；
- 目标 **SDC / 150 MHz STA**。

## 6. 保守 8×16 基线与 16 行候选：同口径 traffic / cycle 公式

同一套口径（16-bit 字、含末行填充、逐块重装描述符）：

```text
traffic_words  = row_tiles*col_tiles*( rows*K + cols*K + cols*2 + rows*cols*2 )
compute_cycles = row_tiles*col_tiles*K*cols          # 每拍 1 个 B 字广播给 rows 行
dump_cycles    = row_tiles*col_tiles*rows*cols        # 串行 CACC/输出导出
load_cycles    = ceil(traffic_words / words_per_beat) # 16-bit 字/拍=1；128-bit=8
serial_total   = load_cycles + compute_cycles + dump_cycles   # 不重叠
overlapped     ≈ max(compute, load + dump)                    # 需真实端口/仲裁证明
```

| 项 | 8×16 基线 | 16 行候选 | 证据层 |
| --- | ---: | ---: | --- |
| tile 数（13/7 行块 × 16 列块） | 208 | 112 | L0 |
| traffic（字 / 字节） | 379,392 / 758,784 | 290,304 / 580,608 | L1（RTL 字数） |
| compute 拍 | 212,992 | 114,688 | L0（row-broadcast 公式） |
| dump 拍（含补零） | 26,624 | 28,672 | L0 |
| load 拍 @16-bit 字/拍 | 379,392 | 290,304 | L0 下界 |
| load 拍 @128-bit/拍 | 47,424 | 36,288 | L0 下界 |
| serial 合计 @128-bit | 287,040 | 179,648 | L0 |
| **测试台 staged 实测** | **251,328** | **154,240** | **L1（仿真总线计时模型）** |
| E203 整层 208-tile 实测 | 838,028 | 无对应模型 | L2（抽象总线） |

另有**旧 8×16 乘积阵列引擎**的结构计数（非 row-broadcast、非实测）：
每 tile `1 + K*(max(R,C)+2) + (R+C+5) + 4*rows*cols`，8×16 = `1,694` 拍/tile、整层 `352,352` 拍。

**必须实测、不能由公式认定的部分**：

1. 赛题 System Bus 的真实宽度、延迟、仲裁 —— 决定 `load_cycles`。
2. 16-bit 宏的读写端口与延迟 —— 决定计算是否能与装载重叠、`compute_cycles` 是否可达。
3. 装载/计算/写回的实际重叠度 —— 决定用 `max` 还是 `+`；L1 的 251,328/154,240 只在该抽象测试台内成立。
4. 150 MHz 时序收敛与 SRAM 宏面积/功耗。
5. 参数装载是否计入（题目规定计入）后的整任务墙钟周期。
6. 有效尾行屏蔽写回是否实现 —— 决定口径是 148,480 还是 153,600。

## 7. 脚本自检与复现

```bash
python3 hardware/optimization/kwt_bus_capacity_model.py \
  --json /tmp/kwt-bus-capacity.json --markdown /tmp/kwt-bus-capacity.md
```

- 退出码 `0`；自检 `PASS`，11 项断言：4 项**RTL 源码片段**（
  `kwt_memory_defs.svh` 的 128-bit 总线、`kwt_tile_system_model.sv` 的 A/W/bias/out 字数表达式与
  `compute_page/load_page` 固定 0、`kwt_operand_pingpong.sv` 的单读/单写口、引擎的 `MAX_LANES` 循环）、
  形状（208/112 tile、padded MAC）、
  修正口径（148,480 / 153,600、147,840 为混用）、
  重复 tile 交通（3,648×208=758,784、5,184×112=580,608）、
  容量（515,584 ≤ 524,288，+12 bias 溢出 2,560）、
  宏端口（2 字/拍、18 拍/K、7.11/14.22 乘积/拍）、
  周期公式（compute/dump/serial）、
  整数范围（A12W10 上界 67,826,716 < 2³¹−1，实测最大 4,733,248）。
  RTL 片段断言保证：若 RTL 改变这些结构，脚本会失败而不是继续引用旧数字。
- 脚本只读 RTL 常量与既有报告，输出 JSON/Markdown 到 `/tmp`，不改仓库文件。

## 8. 本报告未证事项

1. 无平台吞吐：758,784 B、251,328 / 154,240 / 838,028 拍均来自仿真模型，不能当组委会平台耗时。
2. 无总线实测：RTL 字节数是仿真 128-bit 总线 payload，赛题 System Bus 参数未知。
3. 无 150 MHz / STA / 功耗：宏参数与 SDC 缺失。
4. 无面积合规：L3 仅为同库相对标准单元面积。
5. 容量结论不是性能结论：512 KiB 放得下 ≠ 每拍带宽成立。
6. 有效/填充口径取决于尚未实现的尾行写回；现状 RTL 搬运是填充口径。
