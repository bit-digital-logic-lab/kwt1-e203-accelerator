# 本科组 FFN1：分组、混合位宽与 FP8 初测

沿用 [整体量化报告](README.md) 的指定 KWT-1 checkpoint、100 条训练语音、100 条验证语音、12 层 FFN1 输入和 NRMSE 公式。每层计算 `99×64 × 64×256 + bias → 99×256`，最终列出 12 层中的最大误差。混合位宽的层/通道名单只根据训练数据的 INT8 输出误差决定，保存在 `ffn1_parts_mixed_fp8.json`。

## 实际计算边界

- 输出通道分组方案：输入每层一个 INT8 尺度；每 16 个通道或每通道一个 INT8 权重尺度。`int32(qx @ qw + qb)` 完成乘加和 bias，再按对应输出通道尺度反量化。它保持一条完整的整数 MAC 路径，且权重仍为 INT8。
- 输入维每 16 项分块：四组分别做 INT8/int32 部分积，然后将四个部分积反量化，以 FP32 合并并加 FP32 bias。它的 1.58032% 是混合整数/浮点数值结果；若 RTL 要求全整数，需先指定跨组的定点对齐和舍入规则并重测。
- 混合位宽：INT8 路径用 int32 累加，INT16 路径用 int64 累加，bias 在各自整数尺度加入。按层混合选中第 7、8 层；四层方案选中第 4、5、7、8 层。按通道混合每层分别选 26 或 64 个输出通道，这些通道还需要另一份 INT16 编码的输入，因此位宽平均数只表示权重存储，不代表总硬件面积。
- FP8：使用 PyTorch `float8_e4m3fn` 和 `float8_e5m2` 编码并解码操作数，有限值按格式最大值截断；测试原始数值、逐层缩放，以及输出通道分组的权重尺度。乘法、累加和 bias 都由 FP32 执行。本机 Quadro T1000 未运行原生 FP8 GEMM，所以这些结果只衡量 FP8 操作数表示误差，不代表 FP8 硬件的舍入、吞吐、面积或功耗。

INT8 每 16 个输出通道一组只需每层 16 个权重尺度；按 FP32 存尺度，12 层共 768 字节。每通道方案为 12,288 字节，比每 16 通道方案多 11,520 字节，但最大层误差进一步下降 0.305 个百分点。两者的 12 层 INT8 权重本体均为 196,608 字节。该账目尚未包括 bias、输入尺度、寄存器、缓冲和访存对齐。

在这批验证样本上，**输出通道分组 INT8 比按层/通道升 INT16 更划算**：不增加权重位宽，最差层误差还更低。FP8 E4M3FN 的每输出通道缩放为 2.97628%，仅比 3% 低 0.02372 个百分点；其余 E4M3FN 方案和所有 E5M2 方案都超过 3%。即使采用每通道尺度，FP8 E4M3FN 也比相同尺度粒度的 INT8（1.10709%）差得多，因此当前没有足够证据把 FP8 作为本科 FFN1 的优先实现格式。

这是 100 条验证样本的数值试验，不是组委会 600 条样本验收；前端 MFCC 与完整 FP32 模型仍提供各层输入，未做量化误差跨层传播。RTL 逐位一致、尺度表示、饱和、输出定点编码和最坏情况累加位宽尚未验证。

## 复现

在 `software` 目录运行：

```bash
OPENBLAS_NUM_THREADS=4 python3 quantize_parts_mixed_fp8.py --samples .build/quant_samples_10.npz --device cuda
```

逐层误差见 `ffn1_parts_mixed_fp8.csv`；训练/验证文件、混合层与通道名单、累加器峰值及算术边界见 `ffn1_parts_mixed_fp8.json`。代码为 `quantize_parts_mixed_fp8.py`。
