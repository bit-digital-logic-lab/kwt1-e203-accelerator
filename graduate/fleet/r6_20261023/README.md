# R6：按实际8×8/8×16阵列重规划（2026-10-23）

用户纠正：目标是8×8或8×16二维MAC阵列，分别64/128个物理乘法器。旧R4的16路列复用广播单元只是历史对照，121,915周期及其83.15%利用率不可作为目标阵列利用率。本轮准备阶段的32/256路扩展任务已撤掉，未启动。

| 目标阵列 | 物理MAC数 | 1,622,016 MAC纯计算下界 | 99行补到104行的K发射拍 | 局部操作数带宽（A/W16bit） |
| --- | ---: | ---: | ---: | ---: |
| 8×8 | 64 | 25,344 | 26,624 | 8A+8W=32字节/发射 |
| 8×16 | 128 | 12,672 | 13,312 | 8A+16W=48字节/发射 |

下界未计脉动错拍、填充/排空、CACC更新、首次装载和最终写回。按固定8行分块，尾块只有3行有效，5行被屏蔽，行槽利用率99/104=95.19%。

当前真实RTL入口：`hardware/rtl/pulse_array/kwt_product_array.sv`、`kwt_cacc.sv`、`kwt_pingpong_cacc_engine.sv` 和 `hardware/rtl/sram/kwt_operand_pingpong.sv`。静态检查发现每K先串行读max(ROWS,COLS)个lane，再capture和launch，约II10/II18；本轮先测量并消除这个瓶颈。CACC也必须支持64/128个真实productvalid的输出cell归属，不能只改供数后丢产品。累加与bias保留在集中CACC，tile/page标记要随product波前延迟。

外部64/128位总线每拍仅8/16字节，不能直接提供每拍32/48字节的局部供数。必须通过A/W驻留、片内广播复用、分bank同步SRAM、双缓冲和突发加载解耦。A16、W12按16bit容器、bias64、raw输出48bit的候选格式每任务199,552字节：理想64/128位分别24,944/12,472总线拍。此格式宽度尚须按冻结参数实际验证。完美重叠时8×8较适配64bit，8×16较适配128bit；这是待测假设，不是性能结论。无损W12打包能再省8,192字节，但不能凭空改变输出数值。

## 实验分工

12个DeepSeek模型任务同时发出：traffic、bus64、bus128、resident_a、resident_w、output、layout、tail、array8x8、array8x16、feed8x8、feed8x16。完成后依次运行integration、crosscheck，合计14项。起点统一79c8af1，独立工作树/分支，所有权由任务书限定，不自动合并。

不再使用2个DS会话的并发限制，也不设置模型执行超时。CPU密集编译/仿真经heavy.py排队（3个工具槽、每次编译最多2线程），保留原退出码；模型会话可以持续并发。15分钟quarter-hour-check记录进程、结果和结束状态，不自动唤醒主智能体。各任务必须记录真实日志、字节/拍数、有效MAC、气泡、冷启动到末次写回周期、SRAM端口及通用资源，故障必须真实失败。

完成后独立交叉检查，再由主智能体验收。官方SoC/PDK/宏时序/隐藏600样本仍不能由这些开发仿真替代。每条性能结论必须使用相同冻结数值格式，冷任务不借用上个任务缓存，暖多样本另报；PC前端和分类头仍FP32。

## 主智能体实际探针

primary_array_probe.py复用现有RTL，仅在临时TB把K改64、正确扩展独立标量golden并增加握手观测，分别执行8×8/8×16两页任务。8×8：128次K发射，块内间隔10拍，busy1836拍（两块），128个输出校对通过；8×16：128次K发射，块内间隔18拍，busy3388拍（两块），256个输出校对通过。两次构建/仿真退出0。不是整个99×64×256任务周期；逐项信息与源码哈希见primary_array_probe.json，输出见primary_array_probe_raw.txt。
