# R7 缓存组织实验（待验收）

## 容量边界

主智能体已直接查看原题截图：`题目/640.jpg 4`（3/14页）明确写“内部 SRAM 容量由参赛队根据面积与效率确定”；`题目/640.jpg 13`（12/14页）规定新增加速器、接口、内部 SRAM 宏合计 ≤2.25 mm²。共享512 KB单列，不属于新增私有缓存预算。内部宏仅16 bits×128/1024/4096，单口或双口。没有单独的内部缓存字节上限，也不能因此无限增加。

实际容量上限需满足：

`logic_area + interface_area + Σ(macro_count × specified_macro_area) ≤2.25 mm²`

缺少指定宏面积、目标库及冻结配置的综合逻辑面积，故当前最大私有缓存字节数为**未知**，不能把共享512 KB当作内部缓存上限，也不能把任意工艺的面积代入冒充赛题结论。探索16/24/32/48/64/96/128/256 KiB预算不表示这些配置均符合面积/时序。

`python3 graduate/fleet/r7_cache_20261023/capacity.py` 生成 `capacity.json`。它只计算数据容量、指定宏取整和理想搬运下界，**不产生RTL周期或面积结论**。KB暂按KiB解释，正式共享地址范围仍需平台确认。

## 已核对的数据规模

FFN1形状99×64×256；A16、W12存16位容器；CACC40位。

| 数据 | 有效字节 |
|---|---:|
| A | 12,672 |
| A补到104行 | 13,312 |
| 整层W，16位容器 | 32,768 |
| 整层W，无损12位紧排 | 24,576 |
| bias40 | 1,280 |
| 两页8×16 CACC40 | 1,280，仅数据寄存器，未计控制 |
| Y40紧排 | 126,720 |
| Y48容器 | 152,064 |
| Y64容器 | 202,752 |

按最小分配位数、再最少宏数选择，A八bank各832深可用56个16×128宏，分配14 KiB；若优先减少宏数，可用8个16×1024宏，分配16 KiB。这两者**没有面积大小排序结论**，须代入宏面积与外围逻辑。

以A14 KiB、bias1.5 KiB、FIFO128位×64拍取整2 KiB为例：A常驻+W双页合并DP宏约21.5 KiB；W两页分别SP宏约25.5 KiB；A+整层W常驻约49.5 KiB。**未计CACC、标签、流水线及控制寄存器；端口/延迟仍须RTL验证。** SRAM组合选择仅按容量优化，不代表面积最优。

CACC每拍更新128个40位累加器。把每个cell的两页硬塞进独立最小SRAM宏会分配96 KiB；按整体宽字紧排也有80 KiB容量下界，且不自动满足读写时序。因此CACC的1.25 KiB逻辑数据不能直接按1.25 KiB SRAM计面积，应分别比较寄存器实现与可行宏映射。

## 实验顺序与同条件比较

1. 并行运行容量复核、可执行调度模型，以及输出位宽修复。
2. 位宽修复必须通过主智能体预先编写的 `gate_fullwidth.py`：干净Git源码重建、64/128总线、独立任意精度输入/golden和逐值导出检查、故障必须失败。该门禁只属数值预检，**不等于最终验收**。
3. 通过后从同一修复提交建立8个互相隔离的缓存实验分支：W预取页数、W常驻/A分条、A/W全常驻、FIFO深度、CACC页数、无损打包、指定宏端口映射、真实8×8缓存移植。
4. DS交叉复验后结束；主智能体验收前不合并实验分支。

输出修复基线固定为40位CACC符号扩展到64位容器。后续40/48位紧排必须无损，独立证明字节流解码与原64位容器数值相同。旧32位输出的14,441/19,488周期不作为宽输出缓存实验基线。输入、权重、偏置、总线、仲裁、任务起止、输出格式相同才能比较缓存周期。

8×16固定128个物理乘法器，K发射下界13,312拍；8×8固定64个物理乘法器，为26,624拍。冷装载和最终写回另计。不能用16乘法器列复用实现替代目标。

已经每任务只搬一次A/W的方案，再加入整层W缓存未必减少外部字节。重点是消除供数、CACC释放、输出背压的等待。FIFO不能消除长期平均带宽不足；无损W12和Y40/48打包才可能降低必需传输量。64/128位总线分开测，不能为提高占用率而制造重复搬运。
