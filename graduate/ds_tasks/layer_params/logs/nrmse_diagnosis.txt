NRMSE float-comparison diagnosis — layer_params (2026-10-19)
===========================================================

Symptom (main acceptance, no env vars):
  python graduate/ds_tasks/layer_params/verify_manifest.py --device auto  ->  exit 1
  All SHA / training-source / 12x integer weight+bias / INT32 / <3% checks pass;
  11 layers fail the old `abs(measured - recorded) < 1e-9` gate although the
  printed values agree to 6 decimals.

Root cause
----------
`nrmse` compares the dequantized integer result against the FP32 reference
`val_x @ W + b`. That reference is a CPU BLAS reduction (NumPy matmul over
float32), so its summation order -- and hence the recorded percentage -- depends
on:
  * the BLAS/OMP thread count (recorded build ran with OPENBLAS_NUM_THREADS=4
    OMP_NUM_THREADS=4; the acceptance run uses the default thread count = 12);
  * the device that produced the FFN1 inputs (the manifest was frozen on CUDA;
    verifying with --device cpu re-derives the activations on CPU kernels).
The value is reproducible to ~1e-5 relative, not to 1e-9 absolute.

Environment: torch 2.5.1+cu121, numpy 2.1.3, 12 CPU cores, venv python 3.12.12.

Measured deviations from the recorded values
--------------------------------------------
A) Same activations (cached CUDA forward), reference matmul re-run under varying
   BLAS threads (OPENBLAS_NUM_THREADS == OMP_NUM_THREADS):
      1  : max|d| = 1.04e-08 pp
      2  : max|d| = 9.34e-09 pp
      4  : max|d| = 0.00e+00 pp    <- matches the recorded build (thread 4)
      8  : max|d| = 1.99e-08 pp
      12 : max|d| = 1.99e-08 pp    <- acceptance default lands here
B) Cross device, `--device cpu` (default threads):
      max|d| = 1.45e-06 pp, max rel = 1.36e-05 (largest on the small-NRMSE layer 2)
C) Activation-scale provenance (sx = max|train_x| / qmax_a):
      CUDA-frozen vs CPU-recomputed drift: max rel = 2.61e-07
      train-derived vs validation-derived gap: min rel = 1.14e-02 (layer 6)

Chosen tolerances (verify_manifest.py)
--------------------------------------
  NRMSE: |d| <= 1e-6 pp + 1e-3 * recorded
         (~70x the worst cross-device deviation; ~1e3x below the A11W10/A12W10
         scheme gap of ~3.5e-2 pp; ~3e4x below the 3% gate)
  SCALE_RTOL = 1e-5  (provenance of sx)
         (~40x the observed device drift; ~1e3x below the train/val gap)

Negative control
----------------
In /tmp/opencode/manifest_probe a copy of the manifest had L11
validation_nrmse_pct raised by only +0.5% relative (0.147047 -> 0.147782).
verify_manifest.py still FAILs that layer (|d|=7.35e-04 pp > 1.49e-04 pp),
so the tolerance is not vacuous. The frozen NPZ/JSON are never modified.
