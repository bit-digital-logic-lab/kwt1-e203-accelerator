# KWT-1 本科组整体设计决策（2026-10-18）

**范围**：本科必做第 1～3 项——64 点积与数值处理、前馈线性层 `X[99,64]@W[64,256]+b[256]→Y[99,256]`、E203 SoC 集成与综合。12 层为**依次换载 12 套层参数的 12 个独立任务**，不是硬件连续跑 12 层编码器。GELU 与第二线性层为本科**选做**（[`题目/640.jpg 8`](../题目/640.jpg%208) 原文：“GELU 和第二线性层列为本科选做内容”）。

**证据层级约定**（全文沿用）：

| 标记 | 含义 | 例子 |
| --- | --- | --- |
| **L0** | 算术/容量理想计数，无 RTL | MAC 下界、字节数、带宽下界 |
| **L1** | RTL 核 + 测试台仿真（Verilator/Icarus），简化 SRAM/总线模型 | 16 行核 154,240 拍/层；240 样本逐位一致 |

## 0. 关键纠错：当前通过范围（本次独立核验结论）

Claude 审查把**旧的中文路径运行** `real_e203_validation0` 的 0/12 失败当成“当前状态、未修复”。核对真实产物后应记为**过期**：

- 旧运行（`real_e203_validation0_logs/`）：12 个 `.exit` 全为 `1`，每层日志含 `got=xxxxxxxx`，`finalizer.status` = `SUMMARIZE_EXIT 1`。根因是 Icarus `$readmemh` 拒绝路径中的非 ASCII 字节，把向量读成 X（driver 分支已独立复现并修复）。
- 修正运行（**当前**，`real_e203_validation0_ascii_*`）：12 个 `.exit` 全为 `0`，每层恰好一条全层 `PASS`，`finalizer.status` = `SUMMARIZE_EXIT 0`，摘要 `checked_outputs=304128`、`checked_padding=15360`、`total_task_cycles=10056336`。
- 本次独立核验（`docs/check_design_evidence.py`，退出码 0，72 PASS / 0 FAIL）：12 层 `.exit` 与 PASS 行一致；**12 份日志 SHA-256 与摘要逐字一致**；向量 manifest 的 X/W/bias/Y 形状与 hex 行数（6656/16384/256/25344）及全部 SHA-256 正确；A12W10 保守累加上界 67,780,536（INT32 的 3.16%），实测最大 `|expected INT32|` 4,593,325，均 < 2³¹−1。

**因此当前可声明的通过范围**：用**一条**真实验证样本（`validation_index=0`，`four/750e3e75_nohash_0.wav`，`_unknown_`）的 **A12W10** 冻结向量，在 **E203 + 仿真 NICE-like 系统 + 8×16 老引擎 + 仿真 512 KiB 共享 RAM** 上，**12 层各 25,344 个有效 INT32 输出逐位一致（合计 304,128）**。

**仍不能声明**：正式组委会 SoC/总线/PDK/SRAM 宏上的运行；C 驱动在 E203 中执行（现仅宿主编译 + RV32 交叉编译）；官方 600 条评测的精度；150 MHz 时序、≤2.25 mm² 面积与功耗；本 E203 通过路径使用的是 **8×16 老引擎**，**不是** 16 行高性能核。

### 1.2 地址与布局（当前仿真模型约定，非正式平台）

- 旧 E203 模型（`tb_kwt_real_layer_e203.sv`）：`DESC_BASE=0x1000`、`A_BASE=0x3000`、`B_BASE=0x7000`、`BIAS_BASE=0xf000`、`OUT_BASE=0x10000`，共享 RAM 512 KiB。
- 每 tile：`A = A_BASE + rt*1024`、`W = B_BASE + ct*2048`、`bias = BIAS_BASE + ct*64`、`out = OUT_BASE + tile*512`；`tile = rt*16 + ct`（`rt∈[0,12]`、`ct∈[0,15]`，共 208）。
- 描述符 32 B：偏移 `0/4/8/12` = A/W/bias/out 外存字节地址；`16` = `k_len[6:0]`+`relu_en[7]`；`20` = 行掩码 `[7:0]`+列掩码 `[23:8]`；`24/28` 保留为 0。
- 输出写回：INT32 按低 16 位在前拆两字；末行 tile（`rt=12`）行掩码 `7`（仅 3 行有效），填充行必须写 0。
- 这套地址/编码**只与本仓库仿真模型一致**；拿到组委会平台后必须重新核对。

### 1.3 接口假设（须尽早固定，题目未指定唯一答案）

1. **接入方式**：System Bus **或** NICE 二选一（题图第 3 页）。当前实现用 NICE-like 控制 + 128-bit 仿真数据总线，**未证明**符合“选择一种方式”。
2. **数值协议**：A12W10、对称零点 0、rint ties-to-even、有符号 INT32 GEMM+bias；尺度 = 训练集静态最大值 × `2^exp`；字节序小端。
3. **SRAM 映射**：题目给 `16 bits × 128/1024/4096` 单/双口宏。32-bit 部分和与 256×32-bit 输出暂存需**拼宽或串行化**——容量够 ≠ 每拍带宽成立。
4. **任务边界**：单任务从**输入和参数开始装载**计时，到**结果全部写回**结束；任务间测试台复位时间不计入。

## 2. 两条可实施路径

两路径的差别集中在：并行行数、是否重叠 DMA 与计算、权重是否紧凑打包、以及跑在哪个边界上。**路径 A 的 E203 通过结果是 L2 实测；路径 B 的周期是 L1 测试台定时 + 模型推算，不能与路径 A 相减当加速比。**

### 2.1 参数布局

| 项 | 路径 A：保守可交付 | 路径 B：性能优化 |
| --- | --- | --- |
| 计算核 | 现有 **8×16** 乘积阵列 + 行分 bank CACC（已跑通 E203 全层） | **16 行** row-broadcast staged + 输出暂存（`kwt_tile_output_stage`，256×32-bit=1 KiB） |
| A 布局 | `13×64×8`，flat `rt,k,r`，末 tile 行 3..7 补 0 | 同左，行 tile 数 7（`ceil(99/16)`，补到 112 行） |
| W 布局 | `16×64×16`，flat `ct,k,c`；物理 128-bit 字 = 连续 8 个 c lane | 同左，另加 B 列块驻留/双页预装 |
| bias/输出 | INT32；bias 256、Y 99×256 行主序 | 同左 |
| 量化 | **A12W10** 对称、静态最大值尺度（已冻结向量） | 同为 A12W10；可选 A12W12/A14W12 仅在软件验证 |
| 权重打包 | 未打包 int16 容器 | 可选 **W12 紧密打包**（未实现，仅理论容量） |

### 2.2 SRAM 容量与带宽

- 单层操作数（未打包 int16）：A `13,312 B` + W `32,768 B` + bias `1,024 B` + Y `101,376 B` = **147,840 B**（A/W 各读一次、Y 写一次）。
- 12 层权重容器：`393,216 B = 384 KiB`；加输入/输出/bias 后 12 层合计 > 512 KiB → **必须逐层换参**，无选择。
- W12 打包（12 位，~75% 密度）理论：12 层权重 `288 KiB`；单层搬运降至约 `131,592 B`。**未实现打包/解包**，开销未测。
- 共享 SRAM 512 KiB 由题面提供；内部宏须列出**每拍读写端口**才能证明带宽。当前 `kwt_tile_buffers` / `kwt_operand_pingpong` 是 16-bit×1024 单口**行为数组**，不是宏实现。

### 2.3 周期公式与关键数字

- 纯 MAC 下界（P=每拍有效 MAC）：`T_calc_min = ceil(M·K·N / P)`，`M·K·N = 1,622,016`。
  - P=128（8×16 阵列）：`12,672` 拍/L0（要求每拍供 128 个乘积，单口缓存不满足）。
  - 行广播实际（每拍 1 个 B 字广播给 R 行，含填充行）：`T_calc = ceil(M/R)·K·N`。
    - R=8：`13·64·256 = 212,992` 拍；R=16：`7·64·256 = 114,688` 拍。
- 任务周期：`T_task = T_load + T_calc + T_drain + T_wb (+ 总线等待 + 仲裁 + E203 调度)`。
- 搬运下界（未打包 147,840 B）：单 16-bit 字/拍 `73,920` 拍；理想 128-bit/拍 `9,240` 拍。

| 配置 | 每层周期 | 12 层周期 | 150 MHz 换算 | 层级 | 备注 |
| --- | ---: | ---: | ---: | --- | --- |
| 8×16 老引擎 + E203 系统模型（路径 A） | **838,028** | 10,056,336 | 67.04 ms | **L2 实测** | 含装载/计算/写回、仿真总线等待 |
| 16 行 staged 任务模型（路径 B） | **154,240** | 1,850,880 | 12.34 ms | **L1 实测** | 测试台定时装载/写回；含 108,032 拍串行导出 |
| 16 行纯计算（无装载/写回） | 114,688 | 1,376,256 | 9.17 ms | L0/L1 | 模型推算 |
| 128 MAC/拍理想下界 | 12,672 | — | 0.0845 ms | L0 | 需 128 乘积/拍供数，当前不成立 |

> **不可比声明**：`154,240`（16 行 L1）与 `838,028`（8×16 L2）边界不同，**不得相减当作加速比**。base 分支宣称的“1.63×”是 `251,328`（8 行 L1）÷ `154,240`（16 行 L1）——同边界但仍是测试台模型比值，不是平台吞吐。

### 2.4 量化格式与 INT32 边界

保守上界（与样本无关）：`bound = K · qmaxA · qmaxW + max|qbias|`，`qmax = 2^(bits-1) − 1`。

| 方案 | 激活/权重位 | 最差层 NRMSE（软件 L1） | 保守上界 | 占 INT32 | 证据 |
| --- | --- | ---: | ---: | ---: | --- |
| A8W8 | 8/8 | 1.121% | ≪ 上界 | 小 | 480 软件 + 12 样本 RTL 子集 |
| A11W10 | 11/10 | 0.18216% | ~33.9M | 1.58% | 240 样本逐位 RTL |
| **A12W10** | 12/10 | **0.14739%** | **67,826,716** | **3.16%** | 240 样本逐位 RTL + 1 样本 E203 全层 |
| A12W12 | 12/12 | 0.07028% | 271,520,075 | 12.64% | **仅软件** |
| A16W10 | 16/10 | 0.13340% | 1,084,985,265 | 50.52% | **仅软件** |
| A14W12 | 14/12 | 0.03671% | 1,086,478,227 | **50.59%** | **仅软件**（无 RTL 逐位） |

- **A14W12 精度最优但只有软件证据**：`software/compare_ffn1_container.py`（quant 分支，480/480）的整数路径结果，**无 RTL 逐位、无综合**；且保守上界已占 INT32 一半，需显式溢出/饱和处理与更严格的累加器设计。
- **权重位比激活位更划算**（数据支撑仅 A12W12/A16W10/A14W12 三点）：权重 10→12 位使最差层降 52.2%；激活 12→16 位只降 9.3%。但**当前 16-bit 容器下位宽不改变搬运/拍数**，只有真正窄乘法器 + 打包解包才可能有硬件收益。

## 3. Claude 审查逐项裁定

### ✅ 正确

6. 正式 SoC/PDK/SRAM 宏/SDC/600 条评测集缺失。

8. C 驱动仅宿主测试 + RV32 编译，未在 E203 执行。
