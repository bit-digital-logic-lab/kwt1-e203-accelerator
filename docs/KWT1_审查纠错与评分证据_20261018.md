## 1. 逐项纠错

### C1　"GELU 是本科必做 / 精度目标是 `GELU(XW+b)`" —— 错

- **原说法**：根目录 6 份初审文档（`AUDIT_SUMMARY` / `CODE_REVIEW` / `ACTION_PLAN` /
  `QUICK_REFERENCE` / `START_HERE` / `REVIEW_INDEX`）把 GELU 列为本科 P0/BLOCKER，
  用 `GELU(XW+b)` 作为 NRMSE 参考，`--full-12-layers` 关键路径含 GELU 集成。
- **事实**：原题明写"**GELU、第二线性层和注意力不是本科必做内容**"。本科必做止于第一前馈线性层
  `X[99,64]@W[64,256]+b[256]→Y[99,256]`；12 层是依次换参的 12 个独立线性任务，不是硬件连续跑编码器。
  GELU 只能作为通过准入后的选做创新。
- **证据**：`题目/README.md`（§1，第 20 行）；截图 `题目/640.jpg 8`、`640.jpg 9`。主目录 6 份文档
  已有"2026-10-17 范围纠正"抬头（`README_REVIEW.md` 无抬头但不含 GELU 必做断言）。
- **命令/缺口**：`python3 docs/check_review_consistency.py` 第 1 组全"确认"；无需外部资料。

### C2　"旧 0/12 = 当前 12 层失败" vs "12 层已 12/12 通过" —— 需按运行分辨

- **原说法**（packaging 报告）：主目录 `real_e203_validation0` 12 层全 **FAIL(0/12)**，记为未证。
- **事实**：该运行是**旧的中文路径运行**，根因 Icarus `$readmemh` 拒绝非 ASCII 路径 → 读成 X；
  已被 **ASCII 重跑取代**。当前 `real_e203_validation0_ascii` **12/12 通过**：每层 `.exit=0`、
  恰好一条全层 PASS、`finalizer.status=SUMMARIZE_EXIT 0`，合计 304,128 有效输出 + 15,360 填充，
  12 份日志 SHA-256 与摘要逐字一致。旧运行应记为**过期**，不是当前状态。
- **证据**：`results/real_e203_validation0_logs/`（`.exit` 全 1，日志 `got=xxxxxxxx`，
  `SUMMARIZE_EXIT 1`）对 `results/real_e203_validation0_ascii_*`（`.exit` 全 0）；
  `docs/check_design_evidence.py` 的 `superseded/*` 与 `ascii/*` 全部 PASS。
- **命令/缺口**：`python3 docs/check_design_evidence.py --results-dir "/home/yang/Desktop/ic设计竞赛/hardware/architecture/results"`。
  通过范围仅限：**一条**真实验证样本的 A12W10 冻结向量 + **8×16 老引擎** + 仿真 NICE-like 系统；
  正式 SoC/总线/PDK/宏上的运行仍为 GAP。

### C3　"16 行核比 8 行快 1.63× / 提升 38%" —— 边界混用，不能当平台加速比

- **原说法**：`PROGRESS_UPDATE.md` / `README_REVIEW.md` 把"16 行 154,240 拍 vs 251,328 拍 = 1.63×"
  当性能成就；附件把"验证过的核"和"E203 里的核"差异并列为 P0-2。
- **事实**：`154,240` 是 **16 行核在 L1 测试台定时模型**下每层拍数；E203 通过路径用的是
  **8×16 老引擎**，每层 `838,028` 拍（**L2**，含装载/计算/写回与仿真总线等待）。**两者边界不同，
  不得相减当加速比**。`1.63×` 只是 `251,328`（8 行 L1）÷ `154,240`（16 行 L1）的**同边界测试台
  模型比值**，不是平台吞吐，更不是 SoC 级结论。
- **证据**：`results/staged_task_row16_summary.json`（full=154240）；
  `real_e203_validation0_ascii_summary.json`（total_task_cycles=10,056,336=12×838,028）。
- **命令/缺口**：`python3 docs/check_review_consistency.py` 第 3 组；16 行核尚未接入 E203 → 同路径 SoC 吞吐未证。

### C4　"无综合网表、无 SDC、无 STA" —— 绝对化，不准确

- **原说法**（附件 P0-1）："无综合网表、无 SDC、无 STA、无 150 MHz、无面积 sign-off"。
- **事实**：**已有**示例库综合网表（`systolic_nangate45.v`、`systolic_icsprout55.v`、
  `systolic_ics_noexpr.v`，0 条 `assign`）与**探索性 SDC**（`ffn1_8x16_150mhz.sdc`，
  `create_clock -period 6.6667`）。并且 `codex/kwt-sta-followup` 已用 noexpr 网表跑通一次 iSTA
  （EXIT=0，240s 有界），产出 `.rpt` / `.pwr`。但——**该次 STA 时序严重违例**：
  最差 setup slack **−12.298 ns**、等效约 **52.7 MHz**，TNS(max)=**−2770.397**；
  功耗报告 `Net Switch Power == 0`，是**无活动模型的无效结果**。
- **因此准确表述是**：有示例库网表、有探索性 SDC、有一次**跑通但违例**的 iSTA 报告；
  **没有**满足 150 MHz 的可签核 STA，也**没有**有效功耗签核。原题要求的"综合网表 + 时序约束"
  确有雏形，"无网表/无 SDC"绝对说不成立；"**未达标**"才是事实。
- **证据**：`/tmp/kwt-8x16-sta/`（`systolic_*.v`、`*.sdc`、`kwt_systolic_cacc_tile.rpt`、`.pwr`、
  `run_script_stdout.txt`）；源头 `codex/kwt-synth` 的 `hardware/synth/FFN1_8x16_synthesis_status.md`
  记录早期含 `assign` 网表 iSTA `EXIT=134`。这些为**只读外部证据**，本次未改动。
- **命令/缺口**：`python3 docs/check_review_consistency.py` 第 4 组（确认网表/SDC/违例 STA/0 翻转功耗）；
  缺口＝组委会目标 PDK/宏/SDC 下的通过性签核。

### C5　"功耗未测" 与 "功耗按 0" —— 未测≠0，也不得把无效模型当结果

- **原说法**：多个报告把功耗/能耗列为"未做"，部分口径把未建模部分默认按 0 活动/0 功耗推算。
- **事实**：原题明确"**未标注电路不能按零活动处理，未建模 SRAM 不能按零功耗处理**"，且功耗须用
  统一库/工艺角/负载/时钟/互连、同一时间窗口的 SAIF/VCD 估算，含 E203+加速器+互连+SRAM 的
  动态与静态功耗。当前**无 SAIF/VCD**；示例库 iSTA 产出的 `.pwr` 是 `Net Switch Power=0` 的
  退化模型（Total 34.25 W 全为 internal power），**既不能当 0，也不能当有效功耗数**。
- **证据**：`题目/README.md`（§5，第 91 行）；`/tmp/kwt-8x16-sta/kwt_systolic_cacc_tile.pwr`。
- **命令/缺口**：`python3 docs/check_review_consistency.py` 第 4 组末项；缺口＝活动文件 + 目标工艺角功耗签核。

### C6　"RTL 与独立整数 GEMM 逐位一致 = 数值一致性已完成" —— 提交软件模型未冻结

- **原说法**：把"RTL 与内部独立 NumPy INT64 GEMM 低 32 位逐位一致"当作提交数值一致性达成。
- **事实**：题目要求提交**与 RTL 一致的软件数值模型**、参数转换脚本、格式说明，且评测以**被提交
  并冻结**的模型为准，差异未消除即功能不通过。逐位一致目前对的是**内部参考**，不是被正式声明并
  冻结的"提交数值模型"；bias 预舍入、溢出环绕、饱和、打包字节序等协议需在**同一个模型**里定死。
  本地未找到任何"冻结声明/哈希"的提交模型文件。
- **证据**：`题目/README.md`（§4，第 61/65 行；§7 第 108/111 行）；
  `docs/check_review_consistency.py` 第 5 组（"未冻结"确认为真）。
- **命令/缺口**：冻结"X/W/b 布局+尺度+溢出/舍入协议+软件模型哈希"的一次性协议文档，并对 RTL 做端到端对照。

### C7　"效率与创新归零 = 36 分" —— 分值算错

- **原说法**（附件 §1）：准入失败时"40（功能）+ 20（集成）之外，最多 **36 分**直接归零"。
- **事实**：受准入 gate 的"效率与创新项"按评分表为 **吞吐量 8 + 功耗 8 + 加速器面积 4 + 自主创新 20
  = 40 分**；40（功能）+20（集成）=60，100−60=40，与"36"不一致。附件该处应为 **40**。
  准入条件＝完成本组全部必做任务 + 通过必测功能用例 + 数值门槛（NRMSE≤3%）+ RTL 对照 +
  满足时序（150 MHz）和面积（≤2.25 mm²）上限；否则**效率与创新项均计零**。
- **证据**：`题目/README.md`（§5 评分表与准入，第 80–87 行）；截图 `640.jpg 10`、`640.jpg 13`；
  `hardware/architecture/project_review_claude_2026-10-16.md` 亦记"效率(20)+创新(20)"。
- **命令/缺口**：`python3 docs/check_review_consistency.py` 第 6 组；缺口＝在冻结配置上补齐准入各项。

## 5. 未证 / 缺口（一律不计通过）

1. 组委会 System Bus/NICE 规范、SoC 平台工程、PDK、SRAM 宏（16 bits×128/1024/4096）、SDC。
2. 目标库下满足 150 MHz 的时序签核与 ≤2.25 mm² 面积签核；有效 SAIF/VCD 功耗与能耗签核。
3. C 驱动在 E203 仿真中真实执行（现仅宿主测试 + RV32 交叉编译）。
4. 官方 600 条评测集的 NRMSE / 逐位一致。

6. 被正式声明并冻结的"提交软件数值模型"与其哈希。

## 6. 结论（一句话）

可声明的是"**第一线性层数值核与一条真实样本的 E203 全层已逐位通过**"；不可声明的是
"已满足 150 MHz / 2.25 mm² / 功耗 / 官方 600 条 / 提交数值模型冻结"。任何"无网表/无 SDC/无 STA"
的绝对化说法应改为"**有示例库网表与探索性 SDC、有一次违例 iSTA；无达标签核**"；
GELU 不占本科必做；未测功耗不得按 0。
