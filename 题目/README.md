# 芯片设计赛道赛题解读：本科生组

> 依据当前目录中的《嵌入式芯片与系统设计竞赛·芯片设计赛道赛题指南（正式赛题）》15 张截图整理。本文是工作用解读，截图原文仍是最终依据。这里的“本科组”即赛题中的“本科生组”。

## 一句话目标

在组委会给定的 **E203 SoC** 上，实现面向 KWT-1 关键词识别模型的**前馈线性层硬件加速器**：完成长度 64 的点积和必要数值处理，对 12 层编码器的第一层前馈网络依次执行 `99×64 × 64×256 + bias → 99×256`，由 E203 驱动、搬运数据并验证；交付可综合 RTL、软件数值模型、验证工程和逻辑综合结果。[题目简介](<640.jpg 3>)、[本科任务](<640.jpg 8>)、[SoC 与提交要求](<640.jpg 9>)

**本科组必做第 1～3 项；第 4～7 项是研究生组必做、本科组选做。** 本科组完成必做任务后可自行选择流水线、双缓冲、权重复用、低功耗控制、数值表示、完整前馈网络或后续任务作为创新；选做不能替代必做任务。[任务分界](<640.jpg 8>)、[选做说明](<640.jpg 10>)

## 1. 必做、选做和边界

| 项目 | 本科组要求 | 具体验收对象 |
| --- | --- | --- |
| 1. 乘累加与数值处理 | **必做** | 64 项点积、偏置、所需格式转换；正常、边界、复位和连续任务；解释舍入、溢出及误差来源。 |
| 2. 前馈线性加速器 | **必做** | 输入 `99×64`，权重 `64×256`，加偏置得到 `99×256`；参数装载、输入缓冲、计算控制、输出写回；按顺序更换 12 层对应参数并验证。 |
| 3. SoC 集成与综合 | **必做** | 接入 E203，完成驱动、数据交换、启动/完成状态管理和 SoC 仿真；提交 RTL、测试平台、综合网表、时序约束、面积/功耗估计和周期/吞吐记录。 |
| 4～7. 注意力、单层/十二层编码器、综合性能 | **选做** | 本科组可选，不属于前三项的替代品；完整分类头由组委会软件评测程序执行。 |

题目特别写明：**GELU、第二线性层和注意力不是本科必做内容**。因此本科必做的输出是第一层线性层的 `99×256` 张量，并非单层编码器输出、12 层编码器输出或最终分类结果。[模型与范围](<640.jpg 6>)、[后续任务](<640.jpg 9>)

计算必须实际由 RTL 加速器完成，不能让 E203 软件或测试平台代算，再把结果作为硬件输出。输入侧的音频规范化、MFCC、token/位置编码等在计算机端离线完成，不计入硬件必做；题目也不要求重新训练、微调或蒸馏模型。[参赛要求](<640.jpg 5>)、[输入边界](<640.jpg 6>)、[其他约束](<640.jpg 15>)

## 3. 数据流和规模：先把“算什么”说清

组委会从官方模型的 12 个编码器层分别提取**注意力、残差和第一处 LayerNorm 之后、第一处前馈线性层之前**的输入，以及对应权重、偏置；这些提取工作在计算机端离线完成，不算硬件必做。研究生组另提取首层编码器输入。[数据提取边界](<640.jpg 7>)、[续页](<640.jpg 8>)

```text
1 秒语音
  └─ 离线预处理、模型前段与对应层输入提取
       └─ X[layer]：99×64   W[layer]：64×256   b[layer]：256
            └─ E203 装载/调度 → 加速器执行 Y = XW + b → 写回 99×256
                 └─ 软件数值模型逐层、逐元素对照
```

- 每层有 `99×256 = 25,344` 个输出元素，每个输出含 64 项点积。
- 每层为 `99×64×256 = 1,622,016` 次乘累加（MAC）；12 层合计 `19,464,192` 次 MAC。这是**算术规模**，不是时钟周期或实际吞吐量。
- 每层权重 `64×256 = 16,384` 个，共 `196,608` 个；若仅作容量示例，16 bit 存储为每层 32 KiB、12 层 384 KiB，尚未包含偏置、尺度、输入、输出、对齐和控制数据。题目并未规定使用 16 bit，实际布局必须按所选格式重算。
- 初版可用分块计算：按时间维 `T`、输出通道 `N` 和归约维 `K=64` 切块；明确每一块的输入/权重读取次数、部分和驻留位置、写回顺序与 SRAM 端口需求。并行度 `P` 的纯计算理想下界为 `ceil(1,622,016/P)` 周期/层，实际还要计入装载、总线等待、冲突、流水线排空和写回。

## 4. 数据集、数值和 RTL 对照

官方数据为 Google Speech Commands V2 (`speech_commands_v0.02`)。队伍按指定代码处理样本、类别和特征；从**训练划分**取样做无梯度标定，用**验证划分**调试功能/精度。组委会从规定样本和类别规则中选 600 条作统一评测，不另行发布校准/验证/预处理数据包；最终使用队伍冻结的工程和数值配置。[数据规则](<640.jpg 7>)、[评测集](<640.jpg 8>)

本科组必须提交与 RTL 一致的软件数值模型、参数转换脚本和格式说明。以指定开源模型生成浮点参考，按**本设计格式**编码/解码，评测程序比较解码结果；不能把预计算答案藏在样本里，也不能把必做计算移入输入输出适配脚本。[参赛要求](<640.jpg 5>)、[其他](<640.jpg 15>)

本科数值门槛为**归一化均方根误差不超过 3%**。规则是在 600 条样本的 12 层前馈线性输出上，**逐层汇总全部评测样本并取 12 层中最大误差**；每个性能任务也须独立满足 3%。题目称分母为浮点参考结果的均方根，并设 `10^-8` 下限。精度分项的误差为 0 得 10 分，误差每增加 0.3 个百分点扣 1 分，按比例计分、最低 0；这是精度分数的计分方式，**3% 仍是门槛**。最终应以官方评测脚本实现为准，尤其要核对其张量展平和 RMS 计算口径。[精度规则](<640.jpg 11>)、[性能任务](<640.jpg 12>)

RTL 输出还必须与提交的软件数值模型**逐位一致**。适合按以下层次建立验证证据：

1. 官方权重/输入 → 浮点参考：核对 12 层张量形状、参数方向、偏置和导出版本。
2. 浮点参考 → 软件数值模型：报告每层误差及最大层；冻结标定数据、尺度和格式。
3. 软件数值模型 → RTL：点积、偏置、舍入、溢出、复位、连续任务、12 层切换逐位比较。
4. RTL 模块 → E203 SoC：驱动、总线/NICE 协议、参数装载、状态管理、输出地址和综合前后功能一致性。

这里的关键风险是 **“浮点误差合格”与“RTL 逐位一致”是两个独立门槛**；软件仿真精度好不能证明硬件正确。[RTL 对照规则](<640.jpg 11>)

## 5. 计分重点与优化顺序

本科组总分 100，单独排名：[评分表](<640.jpg 10>)

| 评分项 | 本科分值 | 应准备的证据 |
| --- | ---: | --- |
| 功能与数值精度 | 40 | 点积/数值处理 10；前馈线性计算 20（矩阵和偏置 10、12 层参数切换 5、缓冲与写回 5）；精度 10。 |
| SoC 集成、综合与复现 | 20 | 驱动与联调、综合/约束完整性、综合前后功能一致、工程/报告可复现，各 5。 |
| 吞吐量 | 8 | 同一合格冻结配置下的 12 项规定性能任务。 |
| 功耗与单任务能耗 | 8 | 同一合格冻结配置、统一估算条件、SAIF/VCD 活动。 |
| 加速器面积 | 4 | 加速器、接口、内部 SRAM 宏面积；总计 ≤2.25 mm²。 |
| 自主创新 | 20 | 方案与创新说明 8、同条件对照实验 8、答辩与贡献 4。 |

效率和创新项有准入：完成本组全部必做任务、通过必测功能用例和数值门槛、RTL 对照，并满足时序和面积上限。吞吐、功耗、面积须来自**同一个冻结配置**，不能分别拿不同配置的最佳值拼接；无合格设计则效率与创新项计零。[准入与计分](<640.jpg 13>)

性能任务：组委会在提交冻结后，从评测数据抽取 12 个任务；本科覆盖 12 层参数各一次。单任务从**输入和参数开始装载**计时，到**全部结果写回**结束；参数装载、总线等待和 E203 调度均计入。任务开始前清空该任务数据/参数缓存；任务间测试平台复位时间不计入。吞吐量为完成任务数/总运行时间。音频离线预处理、一次性文件格式转换和统一软件分类头不计入。[性能口径](<640.jpg 12>)

功耗用统一库、工艺角、负载、时钟和互连条件，基于相同时间窗口的 SAIF/VCD 做综合阶段估算；包括 E203、加速器、互连和 SRAM 的动态与静态功耗，模拟模块和片外设备不计。未标注电路不能按零活动处理，未建模 SRAM 不能按零功耗处理。单任务能耗为平均功耗 × 总运行时间 / 任务数。面积则按指定范围与宏数据单列，逻辑综合核验，不做物理边长/布线验收。[功耗/面积口径](<640.jpg 12>)、[续页](<640.jpg 13>)

**实际优先级建议**：先冻结参考和逐位数值协议，再打通 1 个点积 → 1 层矩阵 → 12 层换参 → SoC 驱动/写回；接着做 150 MHz、面积、活动文件和完整提交；最后在合格基线上做并行度、复用和缓存创新的同条件对照。该顺序是实施建议，不是题目规定的开发步骤。

## 7. 当前需尽早固定的工程约定

以下由团队选定并写进设计文档/脚本，题目没有指定唯一答案：

- **数值协议**：张量布局与权重转置、位宽/有符号性、尺度/零点、偏置量纲、累加宽度、舍入、饱和/溢出、每级重标定位置、字节序及打包。
- **接口与调度**：System Bus 或 NICE、控制寄存器/指令、起止状态、DMA 或 E203 搬运方式、装载与计算可否重叠、任务边界及缓存清空方法。
- **SRAM 映射**：宏尺寸/端口数、bank 与地址映射、每周期读写请求、权重/输入/部分和/输出的驻留与复用；按宏面积和 150 MHz 验证。
- **可复现清单**：锁定官方提交和权重文件哈希、训练/验证样本 ID、标定脚本与参数、软件/RTL 仿真命令、综合库与 SDC、同一冻结配置标识。
