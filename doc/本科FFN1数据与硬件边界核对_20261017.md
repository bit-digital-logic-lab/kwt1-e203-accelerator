# 本科 FFN1 数据与硬件边界核对（2026-10-17）

依据原题截图（见 `题目/README.md` 的第 1、3、4 节）及本地指定 ARM KWT-1 checkpoint。**必做对象是 12 个独立任务**：逐层给出注意力、残差、第一处 LayerNorm 后的 `X[99,64]` 和该层 `W[64,256]`、`b[256]`，由 RTL 计算 `Y=XW+b[99,256]`。并非让 RTL 从首层编码器输入推完整 12 层；GELU、第二线性层、注意力和分类头属本科选做/软件评测部分。

| 阶段 | 所有权及当前实现 | 数值边界 |
| --- | --- | --- |
| WAV → `98×40` MFCC → CLS/位置编码后的首层 `99×64` | 电脑离线；`software/prepare_quant_samples.py`、`software/offline_encoder_input.py`。6 条真实 WAV 与官方 `SpeechFeatures` 对照最大绝对误差 `6.91711903e-05`（`software/validation/real_input_chain_20261017/manifest.json`）。 | 官方模型输入生成，不是本科 RTL 必做；首层输入**不是** 12 个 FFN1 输入。 |
| 官方 FP32 前向提取 `X[layer]` | 电脑离线，`software/run.py` 的 `forward(..., capture_ffn=True)`；每层在第一处 LayerNorm 后取 `99×64`。 | 冻结指定 checkpoint/推理模式。对这些指定输入做格式编码可以；不能把 `XW+b` 预先算好交给硬件。 |
| FP32 `X/W/b` → 整数与尺度 | 电脑离线标定及打包；当前 A11W10/A12W10 静态对称实验的激活按层一尺度、权重按输出通道尺度，`b_int≈round(b/(s_x s_w))`，见 `software/export_ffn1_quantized.py`。训练划分定尺度；验证/测试划分不用于标定。E203 负责组织任务、装载预编码数据和参数、启动、等待、写回。 | 数值格式可选；当前 NPZ 权重容器实际为 `int16`，A/W 在 RTL 都占 16-bit lane，不能把理论 10-bit/11-bit 紧密打包容量当成已实现带宽或面积收益。 |
| 整数 `XW+b` | **RTL 必做**；当前 16 行 `kwt_row_broadcast_tile` 为 `DATA_W=16`、`ACC_W=32`，`kwt_tile_output_stage` 为 32-bit 输出。当前 Verilator 全层任务由测试台模拟 A/W/bias 装载、预取、共享总线与写回，计算核确实执行整数运算。 | 输出仍是 **INT32**；按 `s_x s_w[channel]` 解码为 FP32 由主机/评测软件完成（`hardware/architecture/run_quantized_ffn1_rtl.py:82-89`），RTL 不含反量化乘法。可选 ReLU 不是 KWT-1 的 GELU；本科必做停在第一线性输出。 |
| E203、DMA、存储 | 旧 `kwt_nice_system_model` 是 NICE-like 指令/描述符、128-bit 仿真总线和 16-bit SRAM 的模型；`kwt_dma` 每 beat 拆八个 16-bit 字，输出 INT32 按低/高 16-bit 两字写回。**当前 16 行 staged 路径未接入该 E203/DMA 系统模型。** | 现有 E203 整层测试使用预打包合成整数，不能外推为真实量化样本的 SoC 联调。正式 System Bus/NICE 平台适配、驱动与真实宏模型仍未闭合。 |

## 存储与可行性

- 题目给共享 SRAM 512 KiB、内部 `16 bits×128/1024/4096` 单/双口宏。当前 `kwt_tile_buffers.sv` 是三块 16×1024 单口**行为数组**；`kwt_memory_defs.svh` 的 128-bit DMA 总线和 16×1024 默认值不等于组委会实际总线/宏的时序实现。
- 当前一个完整 FFN1 任务按未紧密打包 INT16 A/W、INT32 bias/output，最少搬运 `147,840 B`：A `12,672 B`、W `32,768 B`、bias `1,024 B`、Y `101,376 B`。这些数据总量小于共享 SRAM 512 KiB，但宏端口、地址、总线仲裁、任务缓存清空与复用仍需集成验证。12 层应依次换参，不要求片内同时放 12 层。
- 16 行 row-broadcast 核有 16 个并行 32-bit 部分和 bank；输出暂存是 `256×32-bit`（1 KiB）行为数组。赛题宏为 16-bit 宽，若每 bank 每拍都读改写 32-bit，简单拼宽就需每 bank 两个 16-bit 宏或等效端口/流水重构；容量够不代表每拍带宽成立。输出暂存的 32-bit 读写同样需拼宽、序列化或重新设计。
- A11W10 与 A12W10 当前都按 16-bit lane 送入同一 `DATA_W=16/ACC_W=32` 核；若综合参数及结构相同，网表相同。软件有效位宽本身不会带来当前 RTL 的面积、周期或 SRAM 字数差异；需真正实现窄位乘法器、解包和紧密存储后才能比较硬件收益。

## 本轮实际验证与不能外推的结论

| 命令 | 实测 |
| --- | --- |
| `bash hardware/rtl/dma/tb/run.sh` | PASS，装载/写回、尾字、越界及错误描述符。 |
| `bash hardware/rtl/control/tb/run_e203.sh --full-layer` | **旧 NICE-like/E203 系统模型**的 208 tile 整层 PASS：25,344 有效 INT32 输出、1,280 个填充位置，task `838,028` 拍；使用预打包合成整数，与下方真实样本的 16 行 staged 核不是同一硬件边界。 |
| `OUTPUT_STAGE_OUT=/tmp/kwt-output-stage-ownership bash hardware/architecture/run_output_stage.sh` | Verilator 完整/边缘 tile、反压 PASS；Yosys `check -assert` 零问题，识别 1 个 `$mem_v2`。 |
| `OPENBLAS_NUM_THREADS=4 OMP_NUM_THREADS=4 python3 hardware/architecture/run_quantized_ffn1_rtl.py --rows 16 --staged --out /tmp/kwt-ownership-real` | 一条真实验证样本的 12 层、`304,128` 个 INT32 输出与软件整数参考逐位一致；每层 `154,240` 模型拍，最差层 FP32 解码 NRMSE `0.17041%`。 |
| `ROW_BROADCAST_ROWS=16 SYNTH_OUT=/tmp/kwt-ownership-synth-full bash hardware/architecture/run_compare_synth.sh` | 同一 16 行计算核 Yosys `check -assert` 零问题：16 `$mul`、16 `$mem_v2`；Nangate45 示例库将部分和存储展开为触发器后，计算核面积 `120434.692` 库单位。输出暂存另行综合，不在该面积内。 |

`154,240` 拍含测试台设定的装载/写回定时，**不是**真实 E203/组委会总线性能。Nangate45 结果无目标 SRAM 宏、完整 DMA/控制/输出暂存的统一映射，无目标 SDC/STA、功耗、150 MHz 或 `2.25 mm²` 合规证明。单样本 `0.17041%` 也不等于官方 600 条的 12 层最大误差；数值验收还要求 RTL 与提交的软件整数模型逐位一致。
